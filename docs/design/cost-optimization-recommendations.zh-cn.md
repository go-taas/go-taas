## 1. 背景与竞品调研

### 1.1 为什么现在做成本优化建议

平台的分析主干已经完备：成本分析看板（#29）回答*钱花在了哪里*，用量看板（#5）与按 Key 分析（#28）完成归因，预测（#36）回答*未来会是多少*。但没有任何功能回答每个竞品成本页面结尾的那个问题：**"我应该改什么？"**

今天，运营者在 `/admin/cost` 看到某租户在昂贵的大模型上烧预算，必须手工交叉比对价格矩阵（#25）、猜测更廉价的模型是否够用、确认该租户的负载是否真的延迟敏感，还要记得批量 API（#42）有五折优惠。租户在 `/cost` 上可操作的更少。而所有这些判断所需的数据早已结算在平台自己的表里 — 价格、用量明细、服务状态、批量历史 — 只是没有东西把它变成建议。

本功能新增一个**确定性、基于规则的建议引擎**：新的 `optimization` 模块周期性读取已结算用量、价格矩阵与推理服务状态，应用一组**显式、有文档的规则**（§1.5 D3），产出按节省金额排序、可量化、可忽略的建议 — 更廉价模型替换、批量迁移、空闲服务缩容至零、缓存命中率提升 — 每条附带预估月节省金额与一键跳转到运营者或租户执行页面的入口。

### 1.2 访问模式：确定性规则引擎 vs 备选方案

| 模式 | 是什么 | 采用 / 拒绝理由 |
| --- | --- | --- |
| **基于平台自身数据的确定性规则引擎**（采用） | 一组固定、有文档的规则（§1.5 D3）在已结算用量 + 价格 + 服务状态上求值；每条建议携带其规则、输入与算术推导，相同输入永远产出相同建议。 | 唯一**可解释、可测试、诚实**的模式：一条建议就是运营者可以验算的电子表格，不是预言。它复用平台已结算的数据，无需新增埋点。确定性让引擎可单元测试、UI 可在 e2e 中复现。 |
| ML / 异常检测顾问 | 在用量模式上训练的模型来预测浪费或聚类负载。 | v1 拒绝：不可解释的输出（"模型说该换"）无法放心执行，无法确定性 e2e 测试，还引入训练/服务栈换边际收益。平台的成本杠杆少而已知 — 规则即可覆盖。 |
| 实时提示词内容分析 | 检查 prompt/completion 内容以建议压缩、更短系统提示或蒸馏。 | 拒绝：提示词内容是数据导出/隐私边界（#38）下的租户数据；成本顾问不得读取。规则只使用**聚合用量元数据**（token 数、价格、服务状态）。 |
| 自动执行（自动应用） | 平台自行应用建议 — 改价格、迁移流量、缩容服务。 | 拒绝：建议只是参谋；执行（授权模型、编辑路由分组、开启缩容至零、提交批量任务）是带有计费与 SLO 后果的人工决策。引擎绝不写自身建议存储之外的任何东西（D6）。 |
| 在 `/admin/cost` 上加建议 Tab | 把建议折叠进分析页面。 | 拒绝：分析回答*发生了什么*；建议是带自身生命周期（忽略/恢复、刷新节奏、过滤）的可执行工作清单。独立页面保持两者清晰，正如 AWS 把 Cost Explorer 与成本建议分开（D1）。 |

### 1.3 竞品交互模式

| 产品 | 建议模式 | go-taas 决策 |
| --- | --- | --- |
| **AWS Cost Explorer / Cost Optimization Hub** | 独立于浏览器的建议表面；每条建议有预估月节省、资源链接与"查看操作"路径；按节省排序；可忽略。 | 整体采纳该形态：**独立页面**、排序卡片、预估月节省、执行页链接、带理由忽略。AWS 的约 20 种建议类型在 v1 收敛为**四条规则** — 平台的成本杠杆更少且已知。 |
| **OpenAI Platform 用量页** | 按项目支出分解与月度预算告警；无模型替换建议（单一厂商定价）。 | 采纳预算告警的相邻布局（建议紧邻支出上下文）；替换建议只在 go-taas 这样的**多模型市场**目录里才有意义 — 这是差异化，不是照抄。 |
| **Anthropic Console** | 按模型的用量与成本；无建议。 | 印证本功能填补的空白；其控制台模式（按模型归因支出）已由 #29 覆盖。 |
| **Together AI / SiliconFlow** | 模型页并排展示每 1M token 价格；用户手工比较。 | 采纳**建议抽屉内的并排价格对比**（当前模型 vs 建议模型，输入/输出/缓存费率）— 抽屉替用户完成原本要手工做的比较。 |
| **Modal / Baseten** | 按部署的 GPU 小时成本与空闲检测（"此部署已空闲 N 小时"）。 | 采纳空闲检测作为**空闲服务规则** — go-taas 的等价物是未开缩容至零且流量近乎为零的服务；建议链接到弹性伸缩页（#16）。 |
| **vLLM / AIBrix 指南** | 文档级建议：开启前缀缓存、用更短上下文、离线负载走批量。 | 采纳其中两个可度量的：**缓存命中率提升**（计量凭证已记录缓存 token）与**批量迁移**（批量 API 的五折是平台事实）。上下文长度建议无法从结算数据度量 — 排除。 |

### 1.4 仅建议不变式

核心产品规则，与 #49 的不静默替换一脉相承：

1. **引擎绝不行动。** 它只写自己的建议存储。授权模型、编辑路由分组、开启缩容至零、提交批量任务仍是各现有页面上的人工操作。
2. **每个数字可验算。** 建议展示其规则、输入（用量窗口、token 数、价格）与算术推导；相同输入永远得到相同估算。无 ML、无隐藏评分。
3. **建议遵守平台自身的规则。** 替换建议只提出租户已授权（或可授权）的模型；批量迁移建议只在批量 API 服务该模型时触发；空闲服务建议只在弹性伸缩关闭时触发。
4. **建议只是参谋，绝不阻塞。** 请求路径上没有任何东西读取建议存储。忽略一条建议在 UI 之外无任何效果。

### 1.5 决策与范围

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | **两个表面各一个新板块**：管理面 `/admin/optimization` + `/api/v1/admin/optimization/*`（全平台，组织/模型过滤），终端用户面 `/optimization` + `/api/v1/optimization/*`（租户自己的，按组织限定）— **不是** `/admin/cost` 上的 Tab | 建议是带自身生命周期的可执行工作清单，不是分析；两个表面都需要（运营者优化全平台，租户优化自己的支出）— 对应 AWS Cost Optimization Hub 与账户级视图（§1.2） |
| D2 | **新 `optimization` 模块**（`services/optimization`）负责规则引擎、建议存储与忽略/恢复生命周期，拥有独立错误块 **132xx**。它**只读** `billing` 价格/扣费、`metering` 用量、`infer` 服务状态与 `batch` 历史；不写自身表之外的任何数据 | 一个独立的关注点（规则、估算、工作清单生命周期）有自身节奏；专属模块保持分析模块只读、引擎可独立单元测试 |
| D3 | **v1 四条确定性规则**：R1 **更廉价模型替换**（某组织在模型 A 上的流量，存在已授权或可授权的模型 B，B 的上下文长度 ≥ A 的 80% 且有效价格更低，月节省 ≥ ¥100），R2 **批量迁移**（某组织的 Key 月请求 ≥ 1000 且 ≥ 90% 呈非交互形态 — 观测不到延迟 SLO — 且模型支持批量），R3 **空闲服务缩容至零**（未开缩容至零且 7 天日均请求 < 10 的服务），R4 **缓存命中率提升**（某组织/模型对缓存命中率 < 5% 且月提示 token ≥ 1M、模型引擎支持缓存）。每条规则的阈值是**配置常量**，在抽屉中文档化 | 平台的成本杠杆少而已知；四条规则覆盖替换、负载形态、容量与缓存 — 与 AWS 二十种类型收敛后的轴相同。显式阈值保持引擎确定性与文案诚实（§1.2） |
| D4 | **估算是算术，不是预测**：月节省 =（当前有效价格 − 替代有效价格）× 观测月量，所有规则统一使用**同一个 30 天已结算窗口**；抽屉展示输入与公式。无置信区间、无增长假设 — 预测是 #36 | 运营者可逐行验算的建议；把参谋与预言混在一起会让两者都失去信任 |
| D5 | **按预估月节省降序排序**；并列时按规则、目标名次序。列表展示前 50 条；汇总卡片展示预估月节省总额（活跃建议之和）与按规则计数 | 工作清单隐喻：最大的杠杆排最前；总额给出页面的头条数字，与用户看到的行同源计算 |
| D6 | **建议周期性刷新**（默认每小时，`Optimization.RefreshIntervalMinutes`）并**快照化**：每次刷新从已结算数据重算并替换活跃集；**被忽略的建议按指纹持久化**（规则 + 目标 + 建议），指纹仍活跃期间被忽略的建议不会重现。忽略必须填理由（`not_applicable`、`planned`、`other` + ≤ 256 字自由文本）；恢复可撤销。所有忽略/恢复操作均审计 | 确定性重算保持估算诚实；指纹持久化尊重运营者判断而不冻结工作清单；审计轨迹与其他所有可变更表面一致（#22） |
| D7 | **替换建议遵守授权**：R1 只提出该组织**已授权**或公开/可授权的模型 — 抽屉说明属于哪种情况，执行路径是授权页（#13）然后可选路由分组（#49）。引擎绝不提出组织无权调用的模型 | 租户无法执行的建议是噪音；授权检查是平台自身授权规则在建议上的应用（§1.4） |
| D8 | **两个表面共享规则集与卡片/抽屉组件**；管理面增加组织/模型过滤与全平台总额；终端用户面按组织限定并脱敏投影 — 无服务 id、副本数或运营者内部信息（空闲服务规则**仅管理面**：服务是运营者资源）。用户 realm 会话访问管理路由得到 **10038**；无角色会话得到 **10036** | 与控制台表面分离及脱敏投影规则（#17）一致；租户看到自己的支出杠杆，运营者看到全平台的 |
| D9 | **优化块新错误码（13201–13299）**：**13201 `CodeRecommendationNotFound`**、**13202 `CodeRecommendationDismissed`**（重复忽略）、**13203 `CodeRecommendationDismissReasonInvalid`**、**13204 `CodeRecommendationRestoreInvalid`**（恢复未忽略的建议）、**13205 `CodeOptimizationRangeInvalid`** | 新模块（D2）获得 routing 131xx 之后的新块；独立错误码让每种失败模式可操作 |

**范围内**：`optimization` 模块（规则引擎、存储、刷新循环、RPC）；管理页 `/admin/optimization`（汇总卡片、可过滤排序列表、带输入/算术/价格对比的建议抽屉、带理由的忽略对话框、恢复）；终端用户页 `/optimization`（租户自己的卡片/列表/抽屉、忽略/恢复）；执行页链接（授权、路由分组、弹性伸缩、批量提交、定价页）；忽略/恢复审计事件。

**范围外**（由其他功能跟踪或明确排除）：任何建议的自动执行（明确排除，§1.2/D6 — 仅建议）、ML/异常顾问与提示词内容分析（明确排除，§1.2）、预测与置信区间（功能 #36）、成本归因与分析（功能 #29，只读输入）、预算告警与支出限额（功能 #6）、按规则阈值编辑 UI（阈值是配置常量；调优 UI 是后续工作）、建议的邮件/webhook 推送（通知中心 #26 未来可承载）、多币种（平台以单一币种结算，#25）。

## 4. 功能需求

### FR1 — 建议模型与刷新

- **FR1.1** 一条建议为 `{recommendation_id, rule (r1_substitution | r2_batch | r3_idle_service | r4_cache), target_type (org_model | api_key | service | org_model), target_id, target_display (组织名 + 模型名 / Key 名 / 服务名), suggestion (建议的变更，人类可读), estimated_monthly_saving (十进制，2 位小数，平台币种), inputs (按规则：用量窗口、token 数、请求数、价格、缓存率), arithmetic (代入数字后的公式), acting_page (路由 + 标签), status (active | dismissed), dismissed_reason?, dismissed_by?, dismissed_at?, fingerprint, first_seen_at, last_computed_at}`。
- **FR1.2** 引擎按固定间隔运行（默认 60 分钟，`Optimization.RefreshIntervalMinutes`，10–1440），并可由 `RefreshOptimization` 管理触发器显式触发。每次运行从**最近 30 天已结算数据**重算（D4）并替换活跃建议集；被忽略的指纹持久化（D6）。运行是幂等的 — 相同已结算数据产出相同集合。
- **FR1.3** 规则 R1 **更廉价模型替换**：对窗口内请求数 ≥ 1000 且计费 token ≥ 10M 的每个（组织, 模型 A），寻找满足以下条件的候选模型 B：B ≠ A；B 已授权给该组织或公开/可授权（D7）；B 的上下文长度 ≥ A 的 80%；B 的有效价格（按该组织观测 token 结构混合输入/输出）更低；且预估月节省 ≥ 配置下限（默认 ¥100）。建议指名 B；抽屉展示并排价格对比与观测 token 结构。多个 B 符合时建议最便宜的；其余列为备选。
- **FR1.4** 规则 R2 **批量迁移**：对窗口内某（组织, API Key）在批量 API 支持的模型（#42）上请求数 ≥ 1000，且该 Key 的流量呈离线形态（≥ 90% 的请求在业务调整后的高峰时段之外**或** ≥ 90% 的请求提示 token ≥ 512 且无流式），建议迁移到批量 API；节省 = 该 Key/模型观测支出的 50%。抽屉链接到批量提交页。
- **FR1.5** 规则 R3 **空闲服务缩容至零**（仅管理面，D8）：对弹性伸缩未开启或缩容至零关闭、且 7 天日均请求 < 10 的每个推理服务，建议开启缩容至零（#16）；节省 = 该服务的空闲 GPU 成本（副本数 × 卡价 × 24h × 30d，来自加速器清单 #18 与价格矩阵）。抽屉链接到弹性伸缩页。
- **FR1.6** 规则 R4 **缓存命中率提升**：对窗口内提示 token ≥ 1M、缓存命中率 < 5%、且模型引擎支持前缀缓存的每个（组织, 模型），建议开启/组织提示词以利用缓存；节省 =（观测缓存未命中提示 token × 该模型价格的缓存折扣）按平台默认缓存命中假设（50%）估算。抽屉展示当前缓存命中率与定价页链接。
- **FR1.7** 所有刷新运行在 info 级别记录摘要（求值规则数、产出建议数、耗时）；失败在 error 级别记录并保留上一个活跃集（刷新失败绝不清空工作清单）。

### FR2 — 管理面：列表与过滤

- **FR2.1** `ListOptimizationRecommendations`（`GET /api/v1/admin/optimization/recommendations`）返回排序后的活跃建议（D5），支持 `page_size`/`page_token` 分页与过滤：`rule`、`status`（active | dismissed | all，默认 active）、`organization_id`、`model_id`、`min_saving`。每行携带完整 FR1.1 投影。
- **FR2.2** `GetOptimizationOverview`（`GET /api/v1/admin/optimization`）返回汇总卡片：预估月节省总额（活跃）、按规则计数、忽略计数、上次刷新时间、按预估节省排序的第一名组织。
- **FR2.3** `GetOptimizationRecommendation`（`GET /api/v1/admin/optimization/recommendations/{recommendation_id}`）返回单条建议及其完整输入、算术、备选（R1）与忽略状态。未知 id 返回 **13201 `CodeRecommendationNotFound`**。
- **FR2.4** `RefreshOptimization`（`POST /api/v1/admin/optimization:refresh`）触发立即刷新（FR1.2）并返回新摘要。审计（`optimization.refreshed`）。

### FR3 — 忽略与恢复生命周期

- **FR3.1** `DismissRecommendation`（`POST /api/v1/admin/optimization/recommendations/{recommendation_id}:dismiss`）接收必填 `reason`（`not_applicable` | `planned` | `other`），`other` 时必填自由文本备注（≤ 256 字符）。忽略已忽略的建议返回 **13202 `CodeRecommendationDismissed`**；无效理由或超长备注返回 **13203 `CodeRecommendationDismissReasonInvalid`**。操作审计（`optimization.recommendation_dismissed`）并记录操作运营者。
- **FR3.2** `RestoreRecommendation`（`POST /api/v1/admin/optimization/recommendations/{recommendation_id}:restore`）将已忽略建议恢复为活跃。恢复未忽略的建议返回 **13204 `CodeRecommendationRestoreInvalid`**。审计（`optimization.recommendation_restored`）。
- **FR3.3** 被忽略的建议在其**指纹**（规则 + 目标 + 建议）仍处于计算集期间跨刷新保持忽略；条件消失后再次出现且指纹相同时**保持忽略**（指纹而非行是身份）。已忽略行可通过 `status=dismissed` 过滤查看并可恢复（FR3.2）。
- **FR3.4** 终端用户面对租户自己的建议暴露相同的忽略/恢复生命周期（`POST /api/v1/optimization/recommendations/{recommendation_id}:dismiss` / `:restore`），使用相同错误码与审计事件；租户的忽略理由独立 — 不影响管理面对同一底层条件的视图（每个表面维护自己的忽略状态，按表面键控）。

### FR4 — 终端用户面（脱敏投影）

- **FR4.1** `GetMyOptimization`（`GET /api/v1/optimization`）返回调用者组织的汇总卡片与排序活跃建议：仅 R1、R2、R4（R3 仅管理面，D8）。任何字段不含服务 id、副本数、卡价或运营者内部信息；规则过滤中无空闲服务规则。
- **FR4.2** `GetMyOptimizationRecommendation`（`GET /api/v1/optimization/recommendations/{recommendation_id}`）返回本组织的一条建议（属于其他组织的 id 返回 **13201**）；抽屉投影与管理面相同，仅去除运营者内部信息。
- **FR4.3** 终端用户执行链接只指向终端用户页面：模型目录（`/models`）、批量提交页（`/batch`）、定价视图（`/pricing`）与 playground — 绝不指向 `/admin/*`。

### FR5 — 表面、realm 与 API 绑定

- **FR5.1** 引擎管理（刷新触发）与全平台视图仅限管理面（`/admin/optimization` + `/api/v1/admin/optimization/*`）；租户视图是终端用户面（`/optimization` + `/api/v1/optimization/*`）。用户 realm 会话访问管理路由得到 **10038 `CodeRealmMismatch`**；无 platform-admin 角色的会话得到 **10036 `CodeForbidden`**。
- **FR5.2** 两个页面渲染：汇总卡片（预估月节省总额、按规则计数、上次刷新）、排序表格/卡片（规则徽章、目标、建议、预估月节省、状态、首次发现）、过滤（规则、状态、组织 [管理面]、模型 [管理面]、最低节省）、**立即刷新**按钮（管理面）、行抽屉（输入、算术、价格对比 [R1]、备选 [R1]、执行链接、忽略/恢复）。
- **FR5.3** 每个页面提供加载、空态（"暂无建议 — 引擎在最近 30 天未发现省钱机会"）、错误与无权限状态；用户面空态附加"下次刷新后再来看看"。
- **FR5.4** 所有忽略/恢复/刷新变更均审计并记录操作身份（FR3.1–FR3.4、FR2.4）；列表/读取调用不审计，与平台读路径惯例一致。

## 5. 页面与流程设计

### 5.1 表面分配

| 页面 | 表面 | 路由 | API 前缀 |
| --- | --- | --- | --- |
| 成本优化（全平台） | 管理面 | `/admin/optimization` | `/api/v1/admin/optimization/*` |
| 成本优化（我的组织） | 终端用户面 | `/optimization` | `/api/v1/optimization/*` |

### 5.2 页面映射

| 页面 | 表面 | 路由 | 主要组件 |
| --- | --- | --- | --- |
| 成本优化 | 管理面 | `/admin/optimization` | 汇总卡片、过滤栏、排序建议卡片、建议抽屉、忽略对话框 |
| 成本优化 | 终端用户面 | `/optimization` | 汇总卡片（脱敏）、过滤栏（规则/状态/最低节省）、排序卡片、抽屉、忽略对话框 |

### 5.3 页面：`/admin/optimization` — 成本优化（管理面）

**汇总卡片**（顶部）："预估月节省"（头条总额，活跃建议）、"活跃建议"（计数，带按规则徽标）、"已忽略"（计数，链接到已忽略过滤）、"上次刷新"（相对时间 + 立即刷新按钮）。

**过滤栏**：规则（全部 / 替换 / 批量 / 空闲服务 / 缓存）、状态（活跃 / 已忽略 / 全部）、组织（下拉）、模型（下拉）、最低节省（数字）。过滤即时生效。

**建议卡片**（按预估月节省降序）：每张卡片展示规则徽章（按规则配色）、目标（"`<组织>` → `<模型>`" / "`<组织>` / Key `<名称>`" / 服务 `<名称>`"）、建议一句话、**"≈ ¥X / 月"**（预估节省，醒目）、状态（活跃 / 已忽略，悬停显示理由）、首次发现（相对时间）、展开抽屉的箭头。

**抽屉**（右侧）：完整建议 —
1. **是什么**：通俗语言的建议（"将 `<组织>` 在 `<模型 A>` 上的流量切换到 `<模型 B>`"）。
2. **为什么（可验算）**：输入表（用量窗口、请求数、提示/补全 token、观测 token 结构、两个模型的价格 [R1]、缓存命中率 [R4]、空闲 GPU 成本 [R3]）与算术行（"(¥A − ¥B) × 12.4M token ≈ ¥X/月"）。
3. **备选**（仅 R1）：其他符合条件模型及其价格与节省。
4. **执行**：执行页链接（"配置授权" → `/admin/models/{id}/authorizations`、"编辑路由分组" → `/admin/routing-groups`、"开启缩容至零" → `/admin/autoscaling`、"提交批量任务" → `/admin/batch`、"查看定价" → `/admin/pricing`）。
5. **忽略**：忽略按钮打开理由对话框（`not_applicable` / `planned` / `other` + 备注）；已忽略建议展示理由与恢复按钮。

**状态**：加载骨架屏；空态（"暂无建议 — 引擎在最近 30 天未发现省钱机会"）；错误（数据过期带重试）；无权限（标准样式，链接到 `/admin`）。

### 5.4 页面：`/optimization` — 成本优化（终端用户面）

布局与 §5.3 相同，去掉：组织与模型过滤（组织即调用者）、空闲服务规则（不存在）、立即刷新按钮（租户不能触发刷新）、抽屉中的运营者内部信息（R3 的卡价 — R3 不存在；任何地方无服务 id）。执行链接指向 `/models`、`/batch`、`/pricing`、`/playground`。空态附加"下次刷新后再来看看"。

### 5.5 流程

1. **运营者审查全平台省钱机会**（正常路径）：管理员 → `/admin/optimization` → 读头条总额 → 打开顶部卡片抽屉 → 验算 → 点击执行链接 → 在目标页执行 → 返回；下次刷新重算后该条件消失。
2. **运营者带理由忽略**：抽屉 → 忽略 → 理由对话框 → `not_applicable` + 确认 → 卡片移入已忽略过滤；审计轨迹记录运营者、理由与时间；后续刷新保持忽略（指纹）。
3. **租户削减自己的账单**：租户管理员 → `/optimization` → 看到"将 `<模型 A>` 上的流量切换到 `<模型 B>` ≈ ¥X/月" → 验算价格对比 → 打开 `/models` → 切换智能体的模型 → 下次刷新后建议消失。
4. **租户迁移到批量**：租户管理员 → `/optimization` → R2 卡片"Key `<名称>` 的离线负载 → 批量 API ≈ ¥X/月" → 打开 `/batch` → 提交 JSONL 任务 → 在账单上核对五折费率。
5. **运营者开启缩容至零**：管理员 → `/admin/optimization` → 某空闲服务的 R3 卡片 → 抽屉展示空闲 GPU 成本算术 → "开启缩容至零" → `/admin/autoscaling` → 开启 → 下次刷新后卡片消失。
6. **刷新失败**：引擎出错 → 页面展示过期横幅与上次成功刷新时间 → 上一个活跃集保留；错误被记录；下个间隔重试。

## 6. API 表面影响

建议 RPC 属于新 **`optimization` 模块**（D2），经控制网关以 HTTP 服务于**管理前缀** `/api/v1/admin/optimization/*` 与**用户前缀** `/api/v1/optimization/*`。引擎通过内部 RPC 或共享仓储（架构师选择）读取 `billing`、`metering`、`infer` 与 `batch` 数据；只写自己的表。

| RPC | 路由 | 前缀 | 状态 | 用途 |
| --- | --- | --- | --- | --- |
| `GetOptimizationOverview`（新 `taas.optimization.v1`） | `GET /api/v1/admin/optimization` | 管理 | **新增** | 全平台汇总卡片：节省总额、按规则/状态计数、上次刷新、第一名组织 |
| `ListOptimizationRecommendations` | `GET /api/v1/admin/optimization/recommendations` | 管理 | **新增** | 排序建议；分页 + 规则/状态/组织/模型/最低节省过滤 |
| `GetOptimizationRecommendation` | `GET /api/v1/admin/optimization/recommendations/{recommendation_id}` | 管理 | **新增** | 单条建议含输入、算术、备选；未知 id → 13201 |
| `DismissRecommendation` | `POST /api/v1/admin/optimization/recommendations/{recommendation_id}:dismiss` | 管理 | **新增** | 带必填理由忽略；审计 |
| `RestoreRecommendation` | `POST /api/v1/admin/optimization/recommendations/{recommendation_id}:restore` | 管理 | **新增** | 恢复已忽略建议；审计 |
| `RefreshOptimization` | `POST /api/v1/admin/optimization:refresh` | 管理 | **新增** | 触发立即引擎运行；审计 |
| `GetMyOptimization` | `GET /api/v1/optimization` | 用户 | **新增** | 本组织汇总（仅 R1/R2/R4，脱敏） |
| `ListMyOptimizationRecommendations` | `GET /api/v1/optimization/recommendations` | 用户 | **新增** | 本组织排序建议；规则/状态/最低节省过滤 |
| `GetMyOptimizationRecommendation` | `GET /api/v1/optimization/recommendations/{recommendation_id}` | 用户 | **新增** | 本组织单条建议；他组织 id → 13201 |
| `DismissMyRecommendation` / `RestoreMyRecommendation` | `POST /api/v1/optimization/recommendations/{recommendation_id}:dismiss` / `:restore` | 用户 | **新增** | 租户自己的忽略/恢复生命周期 |

**给架构师 agent 的契约说明**：

1. 引擎是 `optimization` 服务内的**周期性批处理任务**（ticker，沿用结算节奏模式）；除 `RefreshOptimization` 外不由请求触发。
2. 30 天窗口、所有规则阈值（FR1.3–FR1.6）与刷新间隔是**配置常量**（`Optimization.*`），在抽屉中文档化；v1 无运行时阈值编辑。
3. `estimated_monthly_saving` 是十进制数，以 JSON **字符串**序列化、保留 2 位小数（int64/十进制转字符串惯例）；币种为平台单一结算币种。
4. 指纹为 `sha256(rule | target_type | target_id | suggestion)`；忽略状态按 `(surface, fingerprint)` 键控（FR3.4）。
5. R3 的空闲 GPU 成本读取加速器清单（#18）与价格矩阵（#25）；任一缺少某服务卡型的数据时，规则**跳过该服务**（绝不产出零节省或无价格的建议）。
6. 序列化惯例不变：成功 HTTP 200，业务错误为 `{"code": <int>, "message": "..."}`，int64 字段为 JSON 字符串。
7. 终端用户 RPC 必须在服务层强制组织限定（从会话取调用者组织），绝不信任客户端传入的组织 id。

错误码（`pkg/errors/codes.go`）：

| 条件 | 码 | 常量 | 说明 |
| --- | --- | --- | --- |
| 未知建议 | 13201 | `CodeRecommendationNotFound` | **新增**（D9） |
| 忽略已忽略的建议 | 13202 | `CodeRecommendationDismissed` | **新增**（D9） |
| 无效忽略理由或超长备注 | 13203 | `CodeRecommendationDismissReasonInvalid` | **新增**（D9） |
| 恢复未忽略的建议 | 13204 | `CodeRecommendationRestoreInvalid` | **新增**（D9） |
| 无效过滤/范围（如 min_saving < 0、错误 status） | 13205 | `CodeOptimizationRangeInvalid` | **新增**（D9） |
| 用户 realm 会话访问管理路由 | 10038 | `CodeRealmMismatch` | 复用 — realm 分离（FR5.1） |
| 会话无所需角色 | 10036 | `CodeForbidden` | 复用 — 权限拒绝（FR5.1） |

## 7. 验收标准

| # | 标准 | 级别 |
| --- | --- | --- |
| AC1 | `/admin/optimization` 渲染汇总卡片（预估月节省总额、活跃/忽略计数、上次刷新）与排序建议卡片（规则徽章、目标、建议、"≈ ¥X / 月"、状态、首次发现） | Nightwatch E2E |
| AC2 | 过滤栏可用：规则、状态（活跃/已忽略/全部）、组织、模型与最低节省过滤列表；排序按预估月节省降序 | Nightwatch E2E |
| AC3 | 抽屉展示输入表、算术行与（R1 的）并排价格对比及备选；执行链接导航到正确页面（`/admin/models/{id}/authorizations`、`/admin/routing-groups`、`/admin/autoscaling`、`/admin/batch`、`/admin/pricing`） | Nightwatch E2E |
